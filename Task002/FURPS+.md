| F1  | Клиент подает заявку на депозит, оставив свои контактные данные |              |
| F2  | Менеджер кол-центра, изучив заявку в системе кол-центра, может предложить особые условия.| |
| F3  | Клиент может посмотреть список доступных депозитов с актуальными и персонализированными ставками |              |
| F4  | Указав счёт и сумму депозита, клиент может подать заявку на открытие депозита |  |
| F5  | Клиент подает заявку на открытие депозита в через интернет-банк |  |

| F10 | Сотрудник отдела кредитования рассчитывает ставки для открытия депозитов (общие и персональные)||
| U   | Удобство использования (Usability) |              |
| U1  | Интерфейс должен придерживаться системы дизайна для приложений, которая принята в компании. Пользователи при работе должны видеть привычные цвета и брендированные элементы |              |Ы
| R   | Надёжность (Reliability)           |              |
| R1  | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев |              |
| R2  | Не должно быть прямой работы интернет-банка с API АБС |              |
| R3  | При сбоях в ЦОД интернет-банк должен оставаться доступным и выдерживать нагрузку до 500 RPS. Необходимо обеспечить горячее резервирование на базе резервного ЦОДа | Для обеспечения оперативного и беспроблемного перехода на резервные источники электропитания. |
| P   | Производительность (Performance)   |              |
| P1  | Отклик системы по всем операциям должен занимать не более 300 миллисекунд |              |
| P2  | Обеспечить горизонтальное масштабирование серверов, приложений и ЦОД  |              |
| S   | Поддерживаемость (Supportability)  |              |
| S1  | Нужно проверить, как разные приложения работают вместе  | Нужно убедиться, что все части системы правильно взаимодействуют друг с другом |
| S2  | Поддержка системы колл-центра | Возможно, потребуется доработка системы колл-центра. Важно, чтобы подрядчик своевременно вносил изменения и обеспечивал необходимую поддержку.  |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | Данные клиента должны передаваться с сайта с помощью механизма шифрования трафика |              |
| +R2 | Ставки по депозитам хранятся только в XLS файлах                                | Функционал можно перенести в АБС |
| +R3 | Технологии должны быть ограничены уже имеющимися в банке. Например, БД MS SQL, Oracle, .Net Framework 4.5, React.js, Java Spring Boot, PHP |  |
| +R4 | Новые технологии должны быть совместимы с уже существующими |  |
| +R5 | Для ассинхронной коммуникации нужно использовать Kafka | Это задел на будущее, который пригодится при переходе на микросервисную архитектуру |
| +R6 | Текущая версия платформы интернет-банка не совместима с Kafka |  |
| +R7 | АБС может масштабироваться только вертикально из-за своей базы данных | Необходимо рассмотреть возможность перехода на горизонтально масштабируемую базу данных |
