**Функциональные требования**
|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
| UC1 | Клиент банка | Звонит в кол-центр, чтобы узнать актуальные условия открытия депозита | Пожилым клиентам может быть сложно разобраться в новых процессах, поэтому они предпочитают уточнять условия по телефону. |
| UC2 | Менеджер кол-центра | Получает свежие данные о ставках из АБС банка и озвучивает их клиенту | Обеспечивает консультацию по условиям открытия депозита. |
| UC3 | Менеджер партнерского кол-центра | Получает актуальные ставки из банка и информирует клиента о возможностях открытия депозита | Снижает нагрузку на основной кол-центр банка, предоставляя консультации клиентам партнера. |


**Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
| 1   | Информация о ставках должна передаваться между банком и кол-центром быстро и надежно |
| 2   | Кол-центр партнера использует отдельную систему, не связанную напрямую с банком |
| 3   | Кол-центр партнера получает ставки через файлы, а не напрямую |
| 4   | Использование API невозможно |

**Решение**

[Контекст](./context.drawio)

[Контейнеры](./container.drawio)


Чтобы добавить новые возможности, нужно обновить систему кол-центра. Теперь она должна получать данные о ставках из Kafka и сохранять их за текущий день. Банк может сделать это своими силами.

Для партнеров потребуется отдельный микросервис. Он будет забирать ставки из Kafka, создавать файл CVC и загружать его в Yandex Cloud. После этого сервис отправит письмо на e-mail партнерского кол-центра со ссылкой на файл в облаке. Такое решение можно быстро и недорого внедрить, а потом легко отключить, если понадобится.

Также нужно доработать АБС, чтобы она каждый день отправляла ставки в Kafka.

**Альтернативы**
Можно сделать микросервис на Python — это быстро, но у банка нет нужных специалистов, придется искать подрядчиков. Еще вариант — использовать Serverless-функцию в Яндекс Cloud, но нужны люди с опытом работы с этим сервисом. Можно отправлять файлы вручную, но тогда легко ошибиться.

**Недостатки, ограничения, риски**

- Сложность реализации нового микросервиса, что потребует дополнительного времени на разработку.
- Практически полностью отсутствует автоматизация процессов.
- Нет альтернативных каналов связи для передачи информации.
